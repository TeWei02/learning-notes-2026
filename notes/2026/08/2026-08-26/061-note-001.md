## 背景

先拿到证据再改代码，日志与指标是第一手材料。这里围绕「慢查询定位流程」做一次整理，重点放在能直接落地的部分。

## 要点

- 先看 slow log 与执行计划，再判断是索引问题还是回表过多
- 覆盖索引可消除回表，但会增加索引体积
- 把排查过程留成记录，下次能少走弯路。

## 示例

```sql
EXPLAIN ANALYZE SELECT id, name FROM t WHERE code = 'x';
```

## 易错点

- 只看 EXPLAIN 不够，实际行数与估算差异大时要 analyze
