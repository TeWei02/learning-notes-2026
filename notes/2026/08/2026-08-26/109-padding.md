# 内存对齐与 padding：重构与可维护性

**日期**：2026-08-26　**领域**：C/C++　**编号**：109/5000

## 背景

先把行为固定住再改结构，避免同时改两件事。这里围绕「内存对齐与 padding」做一次整理，重点放在能直接落地的部分。

## 要点

- 结构体成员按对齐要求排布，调整顺序可减小体积
- alignas 指定对齐，reinterpret_cast 前要确认布局
- 重构后接口不变，调用方无感。

## 示例

```cpp
struct A { char c; int i; };   // 通常 8 字节
struct B { int i; char c; };   // 同样 8 字节但语义更紧凑
```

## 易错点

- 跨平台二进制协议不要直接 memcpy 结构体

## 小结

内存对齐与 padding 在重构与可维护性这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
