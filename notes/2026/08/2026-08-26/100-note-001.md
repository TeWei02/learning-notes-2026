# Git 提交粒度与可回溯性：测试与验证策略

**日期**：2026-08-26　**领域**：工程　**编号**：100/5000

## 背景

测试要覆盖正常、边界与失败三类路径。这里围绕「Git 提交粒度与可回溯性」做一次整理，重点放在能直接落地的部分。

## 要点

- 一个提交只做一件事，便于 revert 与 bisect
- 提交信息写清动机而非仅描述改动
- 测试用例本身也要可维护。

## 示例

```bash
git commit -m "fix(cache): 修正过期判断，避免负 TTL 被当作永不过期"
```

## 易错点

- 混合提交会让回滚牵连无关代码

## 小结

Git 提交粒度与可回溯性 在测试与验证策略这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
