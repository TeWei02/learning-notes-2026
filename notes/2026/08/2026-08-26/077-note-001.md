# 限流的三种实现：版本迁移与兼容处理

**日期**：2026-08-26　**领域**：系统　**编号**：77/5000

## 背景

升级前先确认依赖链上的行为差异。这里围绕「限流的三种实现」做一次整理，重点放在能直接落地的部分。

## 要点

- 计数器简单但有临界问题，漏桶平滑输出，令牌桶允许突发
- 限流维度要能被业务理解，如按用户或按租户
- 灰度期间保留回退路径。

## 示例

```python
allow = token_bucket.try_acquire(cost=1)
if not allow:
    return Response(429, headers={'Retry-After': '1'})
```

## 易错点

- 全局限流和单机限流混用会导致实际配额翻倍

## 小结

限流的三种实现 在版本迁移与兼容处理这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
