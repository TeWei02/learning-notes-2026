# gRPC 流控与超时传递：边界条件与异常路径

**日期**：2026-08-26　**领域**：网络　**编号**：35/5000

## 背景

空集合、极值、超时、部分失败，这几类最容易漏。这里围绕「gRPC 流控与超时传递」做一次整理，重点放在能直接落地的部分。

## 要点

- DEADLINE_EXCEEDED 会在跨服务调用链上传播并逐级缩短
- 流控基于 HTTP/2 窗口，慢消费者会反压上游
- 边界用例应固化成自动化测试。

## 示例

```bash
ctx, cancel = context.with_timeout(ctx, 2.0)
resp = stub.Query(ctx, req)
```

## 易错点

- 忘记取消会泄漏协程与连接

## 小结

gRPC 流控与超时传递 在边界条件与异常路径这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
