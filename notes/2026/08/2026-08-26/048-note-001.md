# 索引失效的常见写法：方案对比与选型

**日期**：2026-08-26　**领域**：数据库　**编号**：48/5000

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「索引失效的常见写法」做一次整理，重点放在能直接落地的部分。

## 要点

- 对列做函数运算、隐式类型转换都会让索引失效
- 前置通配 LIKE '%x' 无法走上索引
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```sql
WHERE created_at >= '2026-01-01'      -- 走索引
WHERE date(created_at) = '2026-01-01'  -- 不走索引
```

## 易错点

- 统计信息过期时执行计划可能偏离，需要 analyze

## 小结

索引失效的常见写法 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
