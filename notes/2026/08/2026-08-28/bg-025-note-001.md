# 日志结构化与检索成本：与相邻技术的配合

**日期**：2026-08-28　**领域**：工具　**编号**：25/9000

## 背景

它很少单独出现，和上下游的约定决定了整体效果。这里围绕「日志结构化与检索成本」做一次整理，重点放在能直接落地的部分。

## 要点

- 统一 JSON 字段名，避免同义字段导致检索遗漏
- 高基数字段不要索引，成本会失控
- 跨组件问题先在边界处抓包或打日志。

## 示例

```yaml
{"ts":"2026-09-14T08:00:00Z","lvl":"error","svc":"api","trace":"7f3a"}
```

## 易错点

- 把完整请求体写进日志会带来合规与容量问题

## 小结

日志结构化与检索成本 在与相邻技术的配合这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
