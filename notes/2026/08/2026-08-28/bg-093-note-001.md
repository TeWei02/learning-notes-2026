# 文本处理的性能差异：边界条件与异常路径

**日期**：2026-08-28　**领域**：Linux　**编号**：93/9000

## 背景

空集合、极值、超时、部分失败，这几类最容易漏。这里围绕「文本处理的性能差异」做一次整理，重点放在能直接落地的部分。

## 要点

- awk 单遍扫描适合列提取，sed 适合流式替换
- 大文件优先用 LC_ALL=C 提升字符处理速度
- 边界用例应固化成自动化测试。

## 示例

```bash
LC_ALL=C awk -F, '$3 > 100 { n++ } END { print n }' big.csv
```

## 易错点

- 默认 locale 下多字节处理会显著变慢

## 小结

文本处理的性能差异 在边界条件与异常路径这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
