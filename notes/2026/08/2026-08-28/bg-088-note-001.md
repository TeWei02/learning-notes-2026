# 分布式锁的续约与释放：性能与复杂度权衡

**日期**：2026-08-28　**领域**：并发　**编号**：88/9000

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「分布式锁的续约与释放」做一次整理，重点放在能直接落地的部分。

## 要点

- 锁需带唯一值以便安全释放，避免删掉他人的锁
- 业务耗时长于租约要续约，续约失败应尽快中止
- 优化前后都要有可复现的基准数据。

## 示例

```cpp
SET lock:job 7f3a NX PX 30000
```

## 易错点

- 用固定值做锁会导致误删

## 小结

分布式锁的续约与释放 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
