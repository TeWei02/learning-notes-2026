# 可观测性三支柱关联：方案对比与选型

**日期**：2026-08-28　**领域**：工具　**编号**：106/9000

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「可观测性三支柱关联」做一次整理，重点放在能直接落地的部分。

## 要点

- 用 trace id 把日志、指标、链路串起来
- 指标看趋势，链路看个案，日志看细节
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```yaml
log.info('order ok', extra={'trace': trace_id})
```

## 易错点

- 缺少 trace 关联会让排障退化为翻日志

## 小结

可观测性三支柱关联 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
