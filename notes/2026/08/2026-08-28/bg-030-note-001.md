# Git 提交粒度与可回溯性：代价与适用边界

**日期**：2026-08-28　**领域**：工程　**编号**：30/9000

## 背景

任何方案都有不适用的时候，提前写清楚。这里围绕「Git 提交粒度与可回溯性」做一次整理，重点放在能直接落地的部分。

## 要点

- 一个提交只做一件事，便于 revert 与 bisect
- 提交信息写清动机而非仅描述改动
- 把不适用条件写进文档，避免误用。

## 示例

```bash
git commit -m "fix(cache): 修正过期判断，避免负 TTL 被当作永不过期"
```

## 易错点

- 混合提交会让回滚牵连无关代码

## 小结

Git 提交粒度与可回溯性 在代价与适用边界这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
