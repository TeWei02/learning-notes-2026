# 表单校验的前后端分工：代码评审关注点

**日期**：2026-08-28　**领域**：Web　**编号**：47/9000

## 背景

评审优先看契约与失败路径，其次才是实现技巧。这里围绕「表单校验的前后端分工」做一次整理，重点放在能直接落地的部分。

## 要点

- 前端校验提升体验，后端校验保证正确性，二者都要有
- 统一错误码便于前端映射提示文案
- 把重复出现的意见沉淀成团队约定。

## 示例

```js
{ "code": "INVALID_EMAIL", "field": "email" }
```

## 易错点

- 只在后端校验会导致用户反复提交

## 小结

表单校验的前后端分工 在代码评审关注点这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
