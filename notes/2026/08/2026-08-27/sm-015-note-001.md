# 读写锁与场景选择：配置与参数调优

**日期**：2026-08-27　**领域**：并发　**编号**：15/9000

## 背景

参数调整必须一次只改一个，否则无法归因。这里围绕「读写锁与场景选择」做一次整理，重点放在能直接落地的部分。

## 要点

- 读多写少用读写锁，写竞争激烈时可能不如互斥量
- 写饥饿需要公平模式或写优先策略
- 调优结论要绑定当时的负载特征。

## 示例

```cpp
std::shared_mutex mu;
{ std::shared_lock lk(mu); read(); }
{ std::unique_lock lk(mu); write(); }
```

## 易错点

- 读锁里做长耗时任务会阻塞写者

## 小结

读写锁与场景选择 在配置与参数调优这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
